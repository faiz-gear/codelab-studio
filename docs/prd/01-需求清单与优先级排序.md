# CodeLab Studio（交互式编程实践学习工作台）— 需求清单与优先级排序

> 文档版本：v1.0  
> 创建日期：2026-11-20  
> 适用范围：交互式编程实践学习工作台（以《Go 与 GoFrame 开发实践手册》为首个标杆内容）  
> 对应阶段：步骤 1（需求探索与结构化）+ 步骤 2（优先级排序与产品规划）

---

## 一、需求摘要与产品定位

### 1.1 一句话产品定位
**CodeLab Studio** 是一款面向个人开发者的**本地交互式编程实践学习工作台**（桌面客户端 / 本地 Web IDE 形态），将任意符合约定的静态 Markdown 开发实践手册转化为「交互式导学手册 + 本地代码工作区 + 一键多终端执行 + 上下文感知 AI 助教 + 自动化证据验收」的一体化实践环境。

### 1.2 核心痛点与需求来源（以《Go 与 GoFrame 开发实践手册》为样本验证）

| 痛点编号 | 现状问题 | 在 Go/GoFrame 手册中的典型体现 | 解决目标 |
|---|---|---|---|
| P-01 | 纯静态文档，缺乏交互式教学与学习闭环 | 手册要求每个练习执行「先预测→再实现→用证据验收→解释原因」四步法，且包含思考题与学习记录模板，但纯 Markdown 无法记录状态、追踪进度或检验理解 | 将静态 Markdown 解析为可交互章节步骤、验收勾选卡片、思考题对话卡与自动沉淀的学习日志 |
| P-02 | 频繁切换编辑器与多个终端，复制粘贴繁琐易错 | 练习 1 需同时开 1 个常驻终端跑 `go run .` 与第 2 个终端发 3 条 `curl -i`；练习 7 需反复在 `go-goframe-learning/`、`task-api/`、`task-api-gf/` 间切换 `cd` | 手册命令块支持一键新建/复用终端并自动定位工作目录，区分常驻服务与单次命令，免复制粘贴 |
| P-03 | 学习产物分散，跨目录查看与比对效率低 | 练习 3 拆分为 `internal/task`、`internal/httpapi` 多文件；练习 7/8 需对比标准库版 `task-api/` 与 GoFrame 版 `task-api-gf/` 的接口行为一致性 | 内置工作区初始化与实时产物文件树，一键查看/编辑源码、对比双项目差异，并支持跳转外部 IDE |
| P-04 | 缺乏代码提示，遇到报错或概念盲区无人即时指导 | 练习 2/4/5/6 涉及 `http.MaxBytesReader`、`database/sql`、`context.Context` 取消链路与并发竞态测试，学习者需手工摘录代码与报错到外部 AI 提问 | 内嵌 Monaco 编辑器并可选接入 LSP（如 `gopls`）提供补全/跳转；支持鼠标划选任意手册/代码/终端报错一键唤起上下文感知 AI 助教 |

### 1.3 已确认的关键产品决策
1. **产品形态**：本地桌面端应用（Tauri/Electron）或本地服务 + 浏览器 UI，直接驱动本机文件系统与真实本机 PTY 终端。
2. **定位范围**：通用型交互式实践手册工具，支持导入解析任意 Markdown 实践手册；《Go 与 GoFrame 开发实践手册》作为内置标杆课程。
3. **编辑与提示深度**：内置轻量代码编辑器（Monaco）+ 可选 LSP 语言提示（如 `gopls`），同时保留「在外部 IDE（VS Code / GoLand）打开」快捷入口。
4. **用户与账号体系**：MVP 面向个人自学者，本地单机零登录运行，学习进度与笔记存本地，AI 能力采用 BYOK（用户自带 API Key / 本地模型）。
5. **AI 助教与验收策略**：AI 默认采用「启发式引导 + 按需给示例」模式；验收支持「手动勾选 + 一键运行验证脚本（如 `curl`/`go test`）自动判定」。

## 二、利益相关者分析与依赖关系

### 2.1 利益相关者矩阵

| 利益相关者 | 角色类型 | 核心诉求 | 关注指标 | 参与方式 |
|---|---|---|---|---|
| **个人开发者 / 自学者** | 最终用户（核心） | 少折腾环境与窗口切换、快速跑通练习、卡壳时得到精准引导、留下可复习的学习产物 | 完课率、单练习耗时、一键执行成功率、AI 答疑采纳率 | 核心使用与反馈 |
| **实践手册作者 / 技术布道师** | 内容生态方（次核心） | 用标准 Markdown 即可编写交互教程，无需学习复杂专有格式，保证教程命令可复现 | 手册零改造兼容率、可选增强元数据上手成本 | 编写/分享 `.md` 手册 |
| **产品与研发团队** | 建设与维护方 | 跨平台稳定（macOS/Windows/Linux）、终端与文件操作安全可控、架构易扩展至多语言 | 崩溃率、启动速度、LSP/PTY 跨平台兼容率 | 设计、研发、迭代 |
| **AI 模型服务商 / 本地推理引擎** | 外部技术依赖方 | 标准 OpenAI-compatible / Anthropic API 协议调用，稳定流式响应 | 首字延迟（TTFT）、调用成功率、Token 成本控制 | 通过用户配置接入 |

### 2.2 外部依赖与前置约束
- **本机开发环境依赖**：运行具体教程依赖本机已安装的语言工具链（如 Go ≥ 1.22、`curl`、`git`，GoFrame 练习需可访问 Go Module 代理或本地缓存），产品需提供**启动前环境体检（Preflight Check）**而非静默报错。
- **终端子系统依赖**：需适配 macOS/Linux (`zsh`/`bash`) 与 Windows (`PowerShell`/WSL) 的 PTY 行为差异及路径分隔符差异。
- **LSP 依赖**：代码补全与跳转依赖本机语言服务器（如 `gopls`），缺失时需平滑降级为纯语法高亮，不得阻断学习主流程。
- **AI 接口依赖**：依赖用户配置的模型 API Key 或本地 Ollama/vLLM 端点；断网或未配置 Key 时，手册、工作区、终端和手动验收必须 100% 离线可用。

## 四、EPIC → 需求项 → 用户故事层级拆解

### 层级总览

```text
EPIC-01：CodeLab Studio 本地交互式编程实践学习工作台
├── REQ-01 交互式手册解析与导学引擎（US-01 ~ US-03）
├── REQ-02 专属学习工作区与代码产物台（US-04 ~ US-07）
├── REQ-03 智能多终端与一键命令执行（US-08 ~ US-10）
├── REQ-04 上下文感知 AI 助教与划词提问（US-11 ~ US-13）
├── REQ-05 四步学习法、自动化验收与进度沉淀（US-14 ~ US-16）
└── REQ-06 环境体检、安全防护与本地设置管理（US-17 ~ US-18）
```

### 详细用户故事与验收标准（INVEST + Given/When/Then）

#### REQ-01：交互式手册解析与导学引擎

- **US-01：导入并解析任意 Markdown 实践手册为交互式课程**
  - **用户故事**：作为个人自学者，我希望直接选择本地任意 `.md` 实践手册（或打开内置的 Go/GoFrame 手册），系统自动将其解析为带章节导航、可执行命令块、代码展示块、验收清单和思考题卡片的交互式手册，以便无需改造原文档就能立即开始互动学习。
  - **验收标准**：
    - `Given` 用户选择本地 `README.md`（如 Go/GoFrame 手册，644 行，含 `## 练习 0` 至 `## 练习 9`）
    - `When` 系统完成解析并加载课程视图
    - `Then` 左侧大纲展示完整章节与进度状态；所有 `bash`/`sh` 代码块自动附带「一键运行」按钮；所有语言代码块（如 `go`/`sql`）附带语法高亮与「复制/写入工作区」快捷动作；包含「验收」「思考」的段落自动识别为高亮交互卡片。

- **US-02：支持可选增强语法元数据（Frontmatter / 代码块属性）**
  - **用户故事**：作为手册作者或进阶学习者，我希望在标准 Markdown 代码块上可选标注工作目录（如 `cwd="task-api"`）、进程模式（`mode="daemon"`）或验收指令（`verify="true"`），以便执行命令时更精准，同时不破坏文件在普通 Markdown 阅读器中的可读性。
  - **验收标准**：
    - `Given` Markdown 代码块头包含扩展属性（如 ```` ```bash cwd="task-api" mode="daemon" ````）或无扩展属性的标准围栏代码块
    - `When` 解析器解析该文档
    - `Then` 有扩展属性时严格按属性生效；无扩展属性时通过启发式规则推断（如上下文出现 `cd task-api`、`go run` 判定为常驻服务）并允许用户在点击执行前微调。

- **US-03：内置标杆课程开箱即用**
  - **用户故事**：作为首次启动产品的学习者，我希望应用内置《Go 与 GoFrame 开发实践手册》示范课程，以便零配置即可体验完整学习工作流。
  - **验收标准**：
    - `Given` 用户首次打开 CodeLab Studio
    - `When` 在欢迎页点击「开始学习：Go 与 GoFrame 开发实践」
    - `Then` 系统引导确认本地工作区目录（默认建议路径，用户可自定义），随后直接进入练习 0 交互式工作台。

#### REQ-02：专属学习工作区与代码产物台

- **US-04：一键初始化与绑定本地学习工作区**
  - **用户故事**：作为自学者，我希望针对每本手册创建或绑定一个专属本地工作区目录，以便所有练习代码、数据库文件、学习进度和记录都集中管理，不污染其他项目。
  - **验收标准**：
    - `Given` 用户创建新学习项目并指定本地目录（如 `~/Work/sandbox/go-goframe-learning`）
    - `When` 点击「初始化工作区」
    - `Then` 若目录不存在则自动创建，并在目录内生成隐藏元数据目录 `.codelab/`（存放进度、日志、会话历史，不干扰源码与 Git），同时在文件树中展示当前工作区结构。

- **US-05：实时产物文件树与一键查看/编辑代码**
  - **用户故事**：作为自学者，我希望在工作区侧栏实时看到学习过程中生成的所有目录和代码产物（如 `task-api/main.go`、`migrations/001_create_tasks.sql`、`task-api-gf/`），点击即可在内置编辑器中查看或修改，以便快速回顾和迭代代码。
  - **验收标准**：
    - `Given` 用户在终端执行 `mkdir task-api && go mod init ...` 或手动创建文件
    - `When` 文件系统发生变更（新增/修改/删除/重命名）
    - `Then` 产物文件树在 500ms 内自动刷新；点击任意文本/代码文件可在内嵌 Monaco 编辑器中打开，支持语法高亮、行号、搜索、`Cmd/Ctrl+S` 保存与未保存红点提示。

- **US-06：轻量级代码提示与语言智能（LSP 可选集成）**
  - **用户故事**：作为自学者，我希望在内置编辑器编写 Go 代码时能获得基础补全、语法错误波浪线和悬停文档提示，以便解决纯文档学习没有代码提示的痛点。
  - **验收标准**：
    - `Given` 本机已安装 `gopls`（或对应语言 LSP）且工作区包含 `go.mod`
    - `When` 用户在 `.go` 文件中输入 `http.` 或将鼠标悬停在 `http.ServeMux` 上
    - `Then` 编辑器在 300ms 内弹出方法补全列表或文档提示；若本机未安装 `gopls`，状态栏温和提示「一键安装 gopls 以启用代码提示」，编辑器仍正常支持语法高亮与基础编辑。

- **US-07：外部 IDE 快捷联动与双项目对照查看**
  - **用户故事**：作为习惯使用 VS Code / GoLand 的开发者，我希望一键在外部 IDE 打开当前工作区或文件，同时能在工作台内一键打开左右分栏对比两份文件（如 `task-api` 与 `task-api-gf` 的 handler），以便兼顾轻量学习与重度编码。
  - **验收标准**：
    - `Given` 工作区已打开任意文件或存在多个项目目录
    - `When` 用户点击「在外部 IDE 打开」或右键文件选择「与另一文件对比」
    - `Then` 外部 IDE 正确定位到当前目录/文件行号；分栏对比视图清晰高亮代码差异且实时同步磁盘修改。

#### REQ-03：智能多终端与一键命令执行

- **US-08：手册命令块一键创建/复用终端并执行**
  - **用户故事**：作为自学者，我希望点击手册中任意命令行代码块上的「运行」按钮，系统自动打开或复用终端并在正确的工作目录下执行该命令，彻底消除复制粘贴和手动 `cd`。
  - **验收标准**：
    - `Given` 用户阅读到练习 1 的 `mkdir task-api && cd task-api && go mod init example.com/task-api` 或练习 3 的 `go test -race ./...`
    - `When` 用户点击该命令块的「一键执行」按钮（或选择「新建终端执行」）
    - `Then` 底部终端面板自动展开，切换到推导/配置的目标 `cwd` 并执行命令，实时流式输出 ANSI 彩色结果并显示执行耗时与退出码（绿色 `0` / 红色非 `0`）。

- **US-09：常驻服务终端与单次命令终端智能隔离**
  - **用户故事**：作为后端学习者，我希望运行 `go run .` 这类长期阻塞的服务命令时，它会在独立的「服务终端」运行并带明显运行态徽章与一键停止按钮，而我再点击后续 `curl` 命令时会自动在另一个「命令终端」执行，不会把 `curl` 误输到运行中的服务进程里。
  - **验收标准**：
    - `Given` 终端 Tab-1 正在运行常驻进程 `go run .`（状态为 `Running`）
    - `When` 用户点击练习 1 的 `curl -i http://127.0.0.1:8080/healthz` 的「一键执行」按钮
    - `Then` 系统检测到当前活跃终端被前台进程占用，自动复用空闲终端或新建 Tab-2 执行 `curl`，并在 Tab-1 保留「停止进程 (Ctrl+C)」和「重启服务」快捷按钮。

- **US-10：多终端标签管理与危险命令二次确认**
  - **用户故事**：作为本地运行命令的用户，我希望自由管理多个终端标签、清空/复制输出，并在命令包含高危操作（如 `rm -rf`、`sudo`、覆盖系统目录）时收到弹窗确认，以便保护本机安全。
  - **验收标准**：
    - `Given` 某 Markdown 手册中包含匹配高危规则的命令（如 `rm -rf`、`sudo`、`curl ... | sh`）
    - `When` 用户点击「一键执行」
    - `Then` 弹出高危命令审查框，明文高亮风险片段和目标路径，仅在用户显式确认后才向 PTY 写入执行。

#### REQ-04：上下文感知 AI 助教与划词提问

- **US-11：鼠标划选代码/手册/终端报错一键提问**
  - **用户故事**：作为自学者，我希望在代码编辑器、学习手册或终端输出区用鼠标选中任意看不懂的代码、概念或报错日志，立即浮现「问 AI 助教」快捷气泡（支持「解释这段代码」「为什么报错」「结合本节提问」），以便零摩擦获取精准解答。
  - **验收标准**：
    - `Given` 用户在 Monaco 编辑器中鼠标选中 `mux.HandleFunc("GET /healthz", ...)`，或在终端选中一段 Go 编译/竞态报错
    - `When` 释放鼠标左键
    - `Then` 在选区附近 150ms 内弹出轻量浮层（不遮挡选中文本），提供「解释代码 / 诊断报错 / 自由提问」按钮；点击后自动展开 AI 助教抽屉并带入选区引用卡片发起流式回答。

- **US-12：四维上下文自动装配与透明展示**
  - **用户故事**：作为自学者，我希望向 AI 助教提问时无需手动描述我在做哪一节练习、当前写了什么代码、刚才终端报了什么错，同时能清楚看到发送给 AI 的上下文清单并可随时增删，以便回答既准确又可控隐私。
  - **验收标准**：
    - `Given` 用户处于「练习 5：事务」并从代码区发起提问
    - `When` 组装 AI 请求上下文
    - `Then` 系统默认附加：①当前章节目标与规则摘要、②用户划选片段及所在文件（截断保护）、③最近一次非零退出码终端输出（可选勾选）；并在输入框上方以可移除 Chip 展示已附加的上下文及预估 Token 数。

- **US-13：引导式教学模式切换与思考题辅导**
  - **用户故事**：作为想真正掌握第一性原理的学习者，我希望 AI 助教默认采用「启发式引导（苏格拉底模式）」帮我推导思路，但在我确实卡住时可以一键切换「直接给方案/代码示例」模式，并支持点击手册中的「思考题」直接和 AI 讨论验证我的理解。
  - **验收标准**：
    - `Given` AI 助教处于默认的「引导模式」
    - `When` 用户针对练习 0 思考题“任务不存在和数据库无法访问，为什么不能都返回同一个错误？”输入自己的答案或请求帮助
    - `Then` AI 先评价用户思路、指出盲点并给出追问线索，而非直接堆砌大段成品代码；用户点击「切换直接解答」后，AI 立即提供完整解析与对比示例。

#### REQ-05：四步学习法、自动化验收与进度沉淀

- **US-14：练习验收清单与一键自动验证**
  - **用户故事**：作为自学者，我希望每个练习的验收项都可以勾选跟踪；对于可命令化验证的条目（如 `go test -race ./...` 或接口状态码检查），支持一键运行验证并自动标记通过/失败，失败时可直接点击「让 AI 诊断原因」。
  - **验收标准**：
    - `Given` 练习 1 验收项配置/识别了验证规则（请求 `/healthz` 返回 `200`、`POST /healthz` 返回 `405`、`/missing` 返回 `404`）
    - `When` 用户点击该练习的「运行验收检查」
    - `Then` 系统按序执行验证命令，逐条展示绿勾（通过）或红叉（失败+实际响应对比），并在失败项旁提供「交给 AI 分析」按钮；支持手动覆盖勾选主观验收项。

- **US-15：四步法学习记录卡片与本地笔记沉淀**
  - **用户故事**：作为遵循实践手册方法论的学习者，我希望在每个练习末尾有结构化的四步学习记录卡（今天要解决的问题 / 我预测会发生什么 / 实际证据是什么 / 我因此修正了什么理解），填写后自动保存并可一键导出为 Markdown 复盘笔记。
  - **验收标准**：
    - `Given` 用户在练习 4 的学习记录卡中填写了预测与实测证据（支持一键引用终端执行快照作为“实际证据”）
    - `When` 点击保存或离开当前章节
    - `Then` 数据实时持久化到本地 `.codelab/notes.json` 并同步生成可读的 `LEARNING_LOG.md`，顶部学习进度条按已验收练习比例更新。

- **US-16：一键创建/写入示范代码（带防覆盖保护）**
  - **用户故事**：作为刚起步的学习者，我希望在手册看到新文件示例（如 `main.go`、`migrations/001_create_tasks.sql`）时，除了手敲，也能在需要时点击「创建到工作区」快速落地文件；若文件已存在，则打开 Diff 视图让我确认，绝不静默覆盖我手写的代码。
  - **验收标准**：
    - `Given` 练习 1 的 `main.go` 代码块带有「写入工作区」按钮
    - `When` 目标路径尚不存在时点击该按钮
    - `Then` 自动创建父目录并写入文件，同时在编辑器中打开；若目标文件已存在，则弹出 Diff 对比视图让用户选择「逐块合并 / 保留本地 / 替换」。

#### REQ-06：环境体检、安全防护与本地设置管理

- **US-17：课程前置环境体检（Preflight Check）**
  - **用户故事**：作为本地运行教程的自学者，我希望打开一本手册时，系统自动检测本机是否具备所需工具链（如 Go 版本 ≥ 1.22、`curl`、`gf`、`gopls`）及网络代理可达性，并给出清晰修复指引，避免练习到一半卡在环境问题上。
  - **验收标准**：
    - `Given` 用户打开《Go 与 GoFrame 开发实践手册》
    - `When` 触发环境体检（首次打开自动触发，后续可手动刷新）
    - `Then` 面板清晰列出 `go version`、`curl`、`gopls`、`GOPROXY` 检测结果（通过/警告/缺失），对缺失项给出可一键执行的安装命令或文档链接。

- **US-18：AI 模型配置（BYOK）与本地隐私安全设置**
  - **用户故事**：作为注重隐私的开发者，我希望自由配置 OpenAI / DeepSeek / Claude / 本地 Ollama 等兼容接口，API Key 加密存储在系统钥匙串，且可随时查看和清空本地缓存与 AI 对话记录。
  - **验收标准**：
    - `Given` 用户进入设置页填写 API Base URL、Model Name、API Key 并点击「测试连接」
    - `When` 发起连通性测试
    - `Then` 3 秒内反馈连通结果与延迟；API Key 通过系统级凭据库（macOS Keychain / Windows Credential Manager）加密保存，绝不明文写入工作区目录或日志文件。

## 五、优先级排序（RICE + MoSCoW + Kano）

### 5.1 RICE 量化评分体系说明
- **公式**：$\text{RICE} = \frac{\text{Reach} \times \text{Impact} \times \text{Confidence}}{\text{Effort}}$
- **口径定义**（面向首期 1,000 名种子开发者/季度的估算基准）：
  - **Reach（覆盖面）**：每季度受影响的学习者人数（100 ~ 1,000）
  - **Impact（影响力）**：3 = 巨大，2 = 高，1 = 中，0.5 = 低
  - **Confidence（信心度）**：100% = 高，80% = 中，50% = 低
  - **Effort（工作量）**：预估研发人周（Person-Week，PW）

## 六、MVP 范围界定与三阶段产品路线图

### 6.1 方案对比与选型结论

| 评估维度 | 方案 A：极简版（仅手册+终端） | **方案 B：标准 MVP 版（推荐采用）** | 方案 C：重型全栈版（含云端与全 IDE） |
|---|---|---|---|
| **核心范围** | Markdown 渲染 + 一键终端 + 基础 AI 聊天框 | **交互手册 + 工作区产物树/Monaco(+Go LSP) + 智能多终端 + 划词四维上下文 AI 助教 + 验收闭环** | 方案 B + 多语言全套调试器 + 云账号 + 团队课程管理平台 |
| **预估周期** | 3～4 周 | **6～8 周（2 名前端/客户端 + 1 名后端/系统研发）** | 16～24 周 |
| **痛点解决度** | 50%（缺代码产物查看与提示，无法真正划选代码问 AI） | **92%（完整覆盖用户 4 大痛点与全部初步期望）** | 100%（但首期过重，验证周期过长） |
| **技术风险** | 低 | 中（PTY 跨平台与 LSP 轻量化集成可控） | 高（云端容器成本高、安全合规重） |

**选定方案**：采用 **方案 B（标准 MVP 版）**，技术架构推荐 **Tauri（或 Electron）桌面客户端 / 本地 daemon + React + TypeScript + Monaco Editor + xterm.js + node-pty/Rust portable-pty**，实现零云端服务器成本、本机原生终端与真实文件系统访问。
