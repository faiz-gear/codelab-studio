## 2. 项目背景与目标收益

### 2.1 项目背景（用户 + 场景 + 问题 + 量化数据）

- **目标用户**：具备基础编程语法能力、通过技术实践手册进行工程进阶的**个人开发者与自学者**（如学习 Go 标准库与 GoFrame 后端工程实践的开发者）。
- **核心场景**：开发者在本地阅读长篇 Markdown 开发实践手册（例如 644 行、涵盖练习 0～9 的《Go 与 GoFrame 开发实践手册》），并按步骤在本地目录中创建项目、编写代码、启动服务、运行 `curl`/`go test` 验证并排查错误。
- **核心问题**：
  1. **纯静态阅读割裂学习闭环**：手册中的四步学习法（预测→实现→验收→解释）、验收项与思考题无法交互打卡或自动校验。
  2. **跨窗口切换与复制粘贴成本高**：以练习 1～9 实测统计，全流程包含 **15+ 组终端命令**，涉及至少 **3 层目录切换**（工作区根、`task-api/`、`task-api-gf/`）及多次**双终端并行操作**（终端 A 常驻 `go run .`，终端 B 执行 `curl` 或 `go test -race ./...`），学习者平均每完成 1 个练习需在阅读器、IDE、终端之间来回切换 **20～35 次**。
  3. **产物分散与代码提示缺失**：学习产物随练习递增至多目录多文件（如练习 3 拆分 `internal/task` 与 `internal/httpapi`，练习 7 同时维护双项目），纯文档场景无代码补全与跳转，定位与对照效率低。
  4. **卡壳答疑上下文搬运成本高**：遇到代码理解障碍、竞态/事务报错或思考题时，需手动复制章节背景 + 代码 + 终端报错到外部 AI 工具，单次排错上下文准备耗时约 **3～5 分钟**。
- **基线量化依据**：基于标杆样本手册《Go 与 GoFrame 开发实践手册》（644 行、10 个练习、6 个核心 REST 接口、2 套项目工程）拆解统计，手工完成全套练习约有 **30%～40% 的时间消耗在窗口切换、命令复制、目录定位与上下文搬运等非核心认知摩擦上**。（注：本项目为 0→1 新产品，暂无历史线上留存基线，以上为标杆手册路径实测估算，将在 Alpha 内测期采集真实基线校准。）

### 2.2 产品定位与核心价值
**一句话定位**：一款面向个人开发者的本地交互式编程实践学习工作台，把任意静态 Markdown 实践手册转化为「交互式导学 + 本地代码工作区 + 一键多终端 + 划词 AI 助教 + 自动验收」的一体化实战环境。

### 2.3 目标与收益

#### 2.3.1 量化目标（v1.0 MVP 发布后 90 天内）

| 目标维度 | 核心指标 | 目标值 | 衡量口径 |
|---|---|---|---|
| **效率提升** | 单练习窗口切换与手动复制粘贴次数 | 较纯文档基线 **下降 ≥ 80%** | 内测对照组任务观察 + 本地埋点（一键执行占比） |
| **学习闭环** | 内置 Go/GoFrame 标杆课程 14 日完课率（完成 ≥ 练习 7） | **≥ 45%**（行业纯文档自学完课率通常 < 15%） | 种子用户匿名自愿上报 / 内测问卷回访 |
| **核心功能采纳** | 一键终端执行成功率（非用户业务代码编译错误） | **≥ 98%** | 本地命令调度日志统计 |
| **AI 助教价值** | 划词/报错提问后单次解决率（用户点赞或未在 3 分钟内重复提问同片段） | **≥ 70%** | AI 对话反馈按钮（有帮助/需改进）统计 |
| **通用扩展性** | 外部标准 Markdown 技术手册零改造导入可解析率 | **≥ 90%** | 20 份典型开源实战教程（Go/Python/Rust/Node）回归测试集 |

#### 2.3.2 达成路径（> 5 人日需求必填）
1. **阶段一（第 1～3 周，核心骨架）**：完成本地工作区管理、Markdown 语义解析器、PTY 多终端后端与三栏 UI 壳，实现「打开手册 → 一键跑通练习 1 双终端（`go run .` + `curl`）」，消除 80% 终端切换摩擦。
2. **阶段二（第 4～5 周，代码与智能）**：接入 Monaco 编辑器、实时文件树监听、`gopls` 可选 LSP 桥接、鼠标划选浮层与四维上下文 AI 助教（BYOK + 钥匙串存储），消除代码查看与提问上下文搬运摩擦。
3. **阶段三（第 6～8 周，闭环与稳健性）**：完成自动化验收运行器、环境体检（Preflight Check）、高危命令拦截、内置 Go/GoFrame 练习 0～9 端到端回归测试与种子用户 Alpha 试跑。

#### 2.3.3 评估方式与时间节点
- **评估方法**：① 20 份外部开源 Markdown 手册自动化解析回归测试；② 招募 15～30 名 Go/后端学习者开展对比内测（A 组纯文档，B 组 CodeLab Studio），对比完成练习 0～5 的总耗时、报错排查耗时、主观测评（SUS 可用性评分 ≥ 80）；③ 上线后 30 天与 90 天收集自愿反馈问卷与本地聚合诊断报告（经用户授权导出）。

## 3. 目标用户与核心使用场景

### 3.1 目标用户画像

| 属性 | 主画像：进阶自学者（小林，工作 1～3 年研发） | 次画像：实践手册作者（老张，技术博主/团队 Tech Lead） |
|---|---|---|
| **技术背景** | 熟悉基础语法，希望通过实战项目掌握后端工程与新框架（如 Go + GoFrame） | 擅长编写高质量 Markdown 实战教程或团队新人上手指南 |
| **核心痛点** | 看长文容易走神、切来切去配环境烦躁、报错不知去哪问、学完没留下结构化代码与复盘 | 教程发出去读者环境五花八门跑不通，又不想花精力维护专有教学平台格式 |
| **核心诉求** | 开箱即用、所见即所跑、代码有提示、卡壳随时问 AI、每步有明确验收反馈 | 继续写标准 Markdown（最多加少量注释级属性），就能让读者获得交互式体验 |

### 3.2 核心用户旅程（端到端）

```text
启动应用 → 选择内置 Go/GoFrame 手册或导入本地 .md → 绑定/创建本地工作区目录
  → 自动执行环境体检（go/curl/gopls/代理） → 阅读练习章节
  → 在代码区编写/查看产物（含可选 LSP 提示） → 点击手册命令块一键启动服务/运行测试
  → 遇不懂代码或终端报错 → 鼠标划选一键问 AI 助教（自动带四维上下文）
  → 点击「运行验收检查」自动核对结果 → 勾选完成并进入下一练习
```

### 3.3 典型业务场景（结合 Go/GoFrame 手册）

- **场景 S1（多终端并行实战 — 练习 1）**：用户读到练习 1，点击 `mkdir task-api && ...` 一键执行初始化；点击 `main.go` 查看并在编辑器中编写代码；点击 `go run .` 一键启动常驻服务终端（Tab-1，标记「服务运行中」）；紧接着点击 3 条 `curl -i` 验证命令，系统自动新建/路由至空闲终端（Tab-2）依次执行，返回 `200`/`405`/`404`，全程零切窗口。
- **场景 S2（划选代码与报错问 AI — 练习 3/5）**：用户在练习 3 运行 `go test -race ./...` 触发竞态警告，在终端用鼠标拖选 `DATA RACE` 报错片段，点击浮窗「诊断报错」，AI 助教自动读取当前练习 3 规则 + `internal/task/memory.go` 锁实现 + 报错栈，用引导式提问指出“分配 ID 与写入 map 未处于同一写锁范围”。
- **场景 S3（跨项目迁移验证 — 练习 7）**：用户按步骤在同级目录执行 `gf init task-api-gf`，文件树实时呈现 `task-api/` 与 `task-api-gf/` 两个目录；用户随时点开旧项目 `handler.go` 对照响应状态码约定，并用同一套验收按钮一键复跑全部接口断言。

### 4.2 核心模块详述

#### 模块 M1：交互式手册解析与导学引擎

**1. 需求描述**
将本地静态 Markdown 文件解析为结构化的交互式教学界面，使开发者在无需修改原手册的前提下获得大纲导航、进度标记、可执行命令块、可交互验收清单与思考题卡片。

**2. 交互逻辑**
1. 用户在欢迎页选择「内置课程：Go 与 GoFrame 开发实践」或点击「打开本地 Markdown 手册」选取 `.md` 文件。
2. 左侧呈现可折叠的「章节大纲」（按 `##` 二级标题拆分，如 `练习 0` ~ `练习 9`），每项显示完成状态图标（未开始/进行中/已验收）。
3. 手册正文区采用高可读性排版，识别并增强以下元素：
   - **Bash/Shell 代码块**：头部渲染目标执行目录标签（如 `cwd: task-api`）、类型标签（常驻服务 / 单次命令），右侧提供「▶ 运行」「+ 新终端运行」「复制」按钮。
   - **源码/SQL 代码块**：带语言标识、语法高亮、「复制」按钮（v1.1 增加「写入工作区」）。
   - **验收区块**（识别 `**验收：**` 或 `### 验收`）：渲染为独立高亮卡片，每条列表项转为可勾选 Checkbox，并附「一键验证」按钮（若配置了自动检查项）。
   - **思考区块**（识别 `**思考：**` 或 `### 思考`）：渲染为问答提示卡片，附「和 AI 助教探讨此题」快捷入口。

**3. 产品逻辑（MECE 解析规则）**

| Markdown 元素 | 解析识别规则 | 默认推断策略 | 用户可覆写能力 |
|---|---|---|---|
| **章节节点** | 一级/二级标题（`#` 作为手册标题，`##` 作为练习/章节节点） | 按文档顺序生成稳定锚点 ID | 不可更改结构，可自由跳转 |
| **可执行命令块** | 围栏语言为 `bash`、`sh`、`zsh`、`shell` | 1. 优先读取围栏扩展属性 `cwd="..." mode="daemon\|oneshot"`<br>2. 无属性时，向上扫描最近 `cd <path>` 推导 `cwd`<br>3. 命令含 `go run` / `npm run dev` / `python -m http.server` / `gf run` 时推断为 `daemon`，否则为 `oneshot` | 点击 `cwd` 标签可在弹窗中临时修改执行目录 |
| **验收项** | 紧邻 `**验收：**` 段落的无序列表 | 默认设为手动勾选类型；内置课程或含 `.codelab-checks.json` 伴生文件时绑定自动验证命令 | 支持自动验证通过后自动勾选，也支持用户手动覆写状态 |
| **思考题** | 紧邻 `**思考：**` 段落的文本或列表 | 绑定当前章节 ID，点击后以「引导模式」唤起 AI 助教 | 用户可先输入自己的思考再提交给 AI 点评 |

**4. 页面元素与校验规则**

| 元素 | 类型 | 说明 | 校验/边界规则 |
|---|---|---|---|
| 本地 `.md` 文件选择器 | 系统文件弹窗 | 仅允许 `.md` / `.markdown` | 文件大小上限 5 MB；非 UTF-8 编码尝试容错读取，失败则提示转码 |
| 命令块 `cwd` 标签 | 可点击 Pill | 展示相对工作区的目标目录 | 若目录尚不存在且命令本身不是 `mkdir`，执行前提示“目录不存在，是否改为工作区根目录执行？” |

**5. 边界条件与异常处理**
- **普通 Markdown 无「练习/验收」字样**：仍按 `##` 生成大纲、正常渲染所有可执行命令块，仅不渲染验收/思考卡片，保证 100% 通用兼容。
- **外部编辑了源 `.md` 文件**：文件监听检测到变更后，在手册顶部弹出非侵入式提示条「源手册已更新，点击重新加载」（保留当前滚动位置与已完成进度）。

**6. 数据埋点**（本地隐私优先，详见第 7 章）
- `manual_import`（source: builtin/local, chapter_count, command_block_count）
- `chapter_switch`（chapter_id, from_outline/scroll）

#### 模块 M2：专属学习工作区与代码产物台

**1. 需求描述**
为每本手册提供隔离的本地学习工作区，统一管理学习过程中产出的所有代码、迁移脚本、数据库与学习元数据，并在工作台内提供实时文件树、轻量级代码编辑器及可选的 Go 语言智能提示。

**2. 交互逻辑**
1. 首次打开手册时，弹窗引导用户确认工作区路径（内置 Go 手册默认建议 `~/codelab-workspaces/go-goframe-learning`，若手册文中存在目录提示则仅供路径名参考，最终由用户确认）。
2. 中栏上部为「工作区面板」，左侧为实时产物文件树，右侧为多标签 Monaco 代码编辑器。
3. 用户点击文件树任意文件，即在编辑器中打开标签页；编辑后出现未保存圆点，`Cmd/Ctrl + S` 落盘。
4. 编辑器顶部栏提供「在外部 IDE 打开」（调用用户配置的 `code` / `goland` / `cursor` 命令）与「在访达/资源管理器中显示」。

**3. 产品逻辑（文件树与 LSP 状态机制）**
- **目录隔离与安全边界**：
  - 所有文件读/写/创建/重命名 API 强制校验规范化绝对路径必须位于 `workspaceRoot` 之下，严格拦截 `../` 路径穿越与指向工作区外的软链接写入。
  - 文件树默认隐藏 `.codelab/`（内部进度存储目录）、`.git/`、`node_modules/`，提供「显示隐藏文件」开关。
- **LSP（`gopls`）生命周期与降级策略**：

| 状态 | 判定条件 | 编辑器能力 | 状态栏表现 |
|---|---|---|---|
| `LSP_READY` | 本机检测到 `gopls` 且当前文件所在子目录存在 `go.mod` | 补全、悬停文档、定义跳转、保存时语法诊断波浪线 | 绿点 `Go LSP: 就绪 (task-api)` |
| `LSP_NO_MODULE` | 检测到 `gopls` 但尚未执行 `go mod init` | 语法高亮、括号匹配、基础词法补全 | 灰点 `Go LSP: 等待 go.mod` |
| `LSP_MISSING` | 本机未找到 `gopls` 可执行文件 | 语法高亮、基础编辑（不阻断使用） | 橙点 `未检测到 gopls（点击一键安装）` |
| `LSP_ERROR` | `gopls` 进程异常退出 | 自动重试 1 次；仍失败则降级为纯高亮 | 红点 `Go LSP 异常（点击重启）` |

**4. 页面元素与校验规则**

| 元素 | 类型 | 说明 | 校验规则 |
|---|---|---|---|
| 工作区路径选择 | 目录选择器 | 绑定当前学习目录 | 必须有当前系统用户读写权限；禁止选择根目录 `/`、`$HOME` 根或系统目录 |
| 新建文件/文件夹输入框 | 内联输入 | 在选中目录下创建 | 禁止空名、禁止含非法路径字符（`..`、非法斜杠）、同名校验提示 |
| 编辑器文件加载 | 代码视图 | 展示与编辑源码 | 超过 2 MB 文本文件或二进制文件（如 `.db`/SQLite 文件、编译产物）禁止以文本编辑器打开，展示文件元信息与“在系统默认应用中打开”按钮 |

**5. 边界条件与异常处理**
- **磁盘外部冲突**：用户同时在外部 IDE 修改了当前已打开文件——若内置编辑器无未保存修改则静默刷新；若有未保存修改，顶部弹出横幅「文件已在外部被修改：[加载磁盘版本] / [保留当前内容]」。
- **多 `go.mod` 子项目切换**（对应练习 7 同时存在 `task-api/` 与 `task-api-gf/`）：LSP 桥接器根据当前活跃编辑文件向上查找最近的 `go.mod` 根目录动态管理独立工作区文件夹，避免双模块包名冲突。

#### 模块 M3：智能多终端与一键命令执行

**1. 需求描述**
在工作台底部内置真实本地多标签 PTY 终端，并与手册命令块深度联动，彻底解决频繁切终端、手敲 `cd`、常驻服务进程与单次验证命令互相干扰的痛点。

**2. 交互逻辑**
1. 点击手册中任意命令块的「▶ 运行」按钮：
   - **第一步：安全扫描**。若命中高危规则，先弹出高危命令审查弹窗，用户确认后继续。
   - **第二步：智能终端路由**。
     - 若命令为 `daemon`（常驻服务，如 `go run .`）：自动创建命名服务终端 Tab（如 `⚡ 服务: go run .`），标注绿色运行脉冲点，并提供「■ 停止」「↻ 重启」按钮。
     - 若命令为 `oneshot`（单次命令，如 `curl`、`go test`）：优先复用当前空闲的普通终端；若当前活跃终端正在运行前台阻塞进程（如 `go run .`），则自动切换至已有空闲终端或新建一个普通终端 Tab 执行，**绝不向运行中的服务进程误输入文本**。
   - **第三步：自动目录对齐与执行**。自动 `cd` 到目标 `cwd` 后执行命令，底部终端面板若处于折叠态则自动展开。
2. 命令执行结束后，在手册对应命令块旁回显状态徽章（`✓ 退出码 0 · 0.4s` 或 `✕ 退出码 1`）；若退出码非 0，终端工具栏高亮提示「✨ 问 AI 诊断错误」。

**3. 产品逻辑（高危命令拦截矩阵）**

| 风险等级 | 命中模式示例 | 系统处理方式 |
|---|---|---|
| **高危（强制拦截确认）** | `rm -rf`、`rm -r /`、`sudo `、`mkfs`、`dd if=`、`chmod -R 777 /`、`curl ... \| sh`、`wget ... \| bash`、对工作区外绝对路径执行重定向覆盖 | 弹出红色警告框：高亮风险片段、展示完整待执行命令与目标目录，默认焦点在「取消」，需用户显式点击「我已了解风险，继续执行」 |
| **中危（提示执行目录）** | 包含全局包安装（`go install`、`npm install -g`、`brew install`）或修改环境变量 | 命令块显示「将影响本机全局环境」微标签，无需阻断弹窗 |
| **安全（直接执行）** | 工作区内 `mkdir`、`go mod`、`go run`、`go test`、`curl`、`ls`、`sqlite3` 等常规开发命令 | 直接路由至对应终端执行 |

**4. 边界条件与异常处理**
- **端口被占用**（如练习 1 与练习 7 同时启动监听 `127.0.0.1:8080`）：捕获 `address already in use` 输出，在终端底部浮现快捷提示「检测到 8080 端口冲突：[查看已运行的服务终端] / [问 AI 如何处理]」。
- **应用关闭或切换工作区时仍有常驻服务运行**：弹窗提示“当前有 N 个运行中的服务进程，关闭将自动终止它们”，确认后向子进程组发送 `SIGINT`（超时 3 秒转 `SIGKILL`），严禁产生孤儿后台进程。
- **超长输出防护**（如死循环打印日志）：单终端界面保留最大 5,000 行滚动缓冲，供 AI 采集的环形缓冲保留最近 200 行（且单次注入做 Token 截断），防止界面卡顿或内存泄漏。

#### 模块 M4：上下文感知 AI 助教与划词提问

**1. 需求描述**
在学习手册、代码编辑器和终端三大核心区域提供“鼠标划选即问”的零摩擦 AI 助教能力，自动装配当前学习全链路上下文，并默认以启发式引导帮助学习者真正理解原理。

**2. 交互逻辑**
1. **触发入口（三种）**：
   - **划选触发（核心）**：在手册正文、Monaco 代码编辑器或 xterm.js 终端输出中用鼠标选中任意非空文本（≥ 2 个字符），松开鼠标后 150ms 内在选区右上/下方浮现紧凑操作条：
     - 手册选区：`[✨ 解释概念]` `[💬 提问]`
     - 代码选区：`[✨ 解释代码]` `[🔍 找潜在问题]` `[💬 提问]`
     - 终端选区：`[🩺 诊断报错]` `[✨ 解释输出]` `[💬 提问]`
   - **快捷入口**：点击手册思考题卡片的「和 AI 探讨」，或点击终端/验收失败项旁的「让 AI 诊断」。
   - **主动对话**：点击右上角打开 AI 助教抽屉直接输入。
2. **上下文透明控制**：AI 抽屉输入框上方以可关闭的 Chip 展示本次将发送的上下文（如 `[📖 练习 5：事务]` `[📄 memory.go:L42-L68]` `[💻 终端报错 · 38行]`），用户可点击 `×` 移除任意项或悬停预览具体发送内容。
3. **教学风格切换**：抽屉头部提供分段开关 `🧭 引导模式（默认） | ⚡ 直接解答`：
   - **引导模式**：AI 优先肯定正确部分 → 指出关键原理或报错线索 → 提出 1 个引导性问题，不直接倾倒整文件成品代码。
   - **直接解答**：直接给出根因分析、精简对照代码与验证步骤。

**3. 产品逻辑（四维上下文装配与 Token 预算策略）**

| 优先级 | 上下文维度 | 来源 | 预算占比/截断策略 |
|---|---|---|---|
| **P0（永不截断）** | 用户提问 + 鼠标划选片段 | 当前选区（上限 2,000 字符） | 优先完整保留 |
| **P1** | 所在代码文件上下文 / 最近终端报错尾 | 选区前后各 40 行代码；终端最近非零退出输出的最后 80 行 | 超出总预算（默认 6,000 input tokens）时优先保留报错尾与选区邻近行 |
| **P2** | 当前练习章节摘要与验收规则 | M1 解析出的当前章节标题、规则约束与验收列表 | 压缩至 ≤ 800 tokens |
| **P3** | 当前对话历史轮次 | 同工作区当前章节会话历史 | 滑动窗口保留最近 6 轮，超限自动丢弃最早轮次 |

**4. 异常与降级处理**
- **未配置 API Key**：点击任何「问 AI」入口时，右侧抽屉优雅展示引导卡片「配置你自己的 AI 模型（支持 OpenAI / DeepSeek / Claude / 本地 Ollama）」，提供一键跳转设置页按钮，不报错崩溃。
- **网络超时 / 401 鉴权失败 / 429 限流**：在消息气泡内展示人类可读错误原因（如“API Key 无效或额度不足”）+ `[重试]` / `[修改模型配置]` 按钮；支持生成中途点击「■ 停止生成」。
- **敏感信息防泄漏提醒**：首次发送代码至云端 AI 接口前弹出一次性隐私告知弹窗（说明本地代码片段将发送至用户自选的模型服务商，支持切换本地 Ollama 全离线运行）。

## 6. 灰度方案

本项目为本地安装型单机桌面/本地客户端工具，不涉及服务端在线流量切分，但仍执行**分阶段发布与灰度验证策略**，控制跨平台环境风险：

| 灰度阶段 | 目标人群与规模 | 持续时间 | 发布渠道 | 核心监控/验收指标 | 回滚/止损方案 |
|---|---|---|---|---|---|
| **Stage 1：内部 Alpha** | 研发/产品内部成员（5～10 人，覆盖 macOS M 系列 + Windows 11） | 1 周 | 内部分发安装包 | 跑通 Go/GoFrame 练习 0～9 零 P0 崩溃；PTY 与 `gopls` 无孤儿进程 | 发现阻塞缺陷立即停发并修复后重新出包 |
| **Stage 2：种子用户 Beta** | 招募 30～50 名真实学习者（含 macOS/Windows/Linux） | 2 周 | 定向邀请 + GitHub Pre-release | 一键命令成功率 ≥ 98%、冷启动 ≤ 2s、SUS 评分 ≥ 80、核心痛点反馈闭环 | 保留上一稳定版本安装包下载入口；自动更新支持用户手动关闭或回退版本 |
| **Stage 3：v1.0 正式发布** | 全体个人开发者 | 长期 | 官网 / GitHub Release | 崩溃反馈率 < 1%、30 天留存与完课问卷达标 | 发现严重安全/崩溃问题 24 小时内撤回最新 Release Tag 并推送热修版 |

## 7. 数据埋点与数据报表需求

### 7.1 隐私优先数据采集原则
CodeLab Studio 采用**本地优先、零强制上报**架构：
- **默认完全本地记录**：学习行为仅保存在本地 `.codelab/metrics.json`，用于驱动个人「学习进度概览」与帮助用户导出复盘。
- **可选匿名遥测（Opt-in）**：仅在用户设置中显式开启「帮助改进产品（匿名使用统计）」后，才上报脱敏聚合事件，**严禁上报源码内容、命令明文、文件路径、AI 对话原文及 API Key**。

### 7.2 核心埋点事件表

| 事件名称 | 触发时机 | 关键参数（全部脱敏） |
|---|---|---|
| `workspace_initialized` | 初始化/绑定工作区成功 | `course_type` (builtin/custom), `os_platform` |

## 8. 风险、合规披露与依赖项

### 8.1 资金风险判断（必填）
- **是否跟钱相关**：**否（产品本身免费、无支付/充值/订阅/虚拟币/交易结算链路）**。
- **间接费用风险及等级**：**低风险**。用户采用 BYOK 自行接入第三方大模型 API（如 OpenAI / DeepSeek / Anthropic）会产生用户侧 API Token 账单。
  - **缓解措施**：① 单次上下文强制 6,000 input tokens 上限截断；② 每次发送前通过上下文 Chip 透明展示附带内容；③ 支持零成本本地模型（Ollama）。

### 8.2 数据泄露与隐私风险披露（必填）
- **风险存在性**：**存在中度本地敏感信息外传风险**（两类风险点）：
  1. **API Key 泄露风险**：若误存明文配置文件，可能随用户 `git push` 练习工作区泄露至 GitHub。
  2. **本地源码发送至第三方 AI 风险**：划选代码或自动附带文件内容发送给外部模型服务商。
- **防护与合规措施**：
  - API Key 强制走操作系统原生加密凭据库（Keychain / Credential Manager），绝不写入工作区目录；`.codelab/` 自动建议加入 `.gitignore`。
  - 首次调用外部 AI 接口前强制展示明示告知与确认；每次提问以可移除 Chip 明示发送范围；屏蔽 `.env`、`*secret*`、`*key*` 文件被自动带入 AI 上下文。
  - 隐私协议与法务沟通结论：v1.0 为纯本地开源/免费个人工具，不收集个人身份信息（PII），不代持用户模型数据；发布公测前需由法务/合规复核开源协议（MIT/Apache-2.0）与用户隐私声明文本。

### 8.3 其他合规与安全风险披露
- **本地任意命令执行安全风险（高关注）**：导入不可信第三方 Markdown 手册可能含恶意 Shell 脚本。
  - **应对措施**：所有命令块默认**严禁自动静默执行**，必须由用户主动点击；命中高危命令正则规则强制弹窗二次审查；首次打开非内置外部 `.md` 手册时弹出「信任此手册来源」提示。
- **第三方开源组件与外部内容版权风险**：
  - 需确保 Monaco Editor、xterm.js、PTY 库等依赖许可证兼容；内置示范教程需获原作者授权（当前《Go 与 GoFrame 开发实践手册》由需求提出人自有提供）。

### 8.4 技术与外部依赖

| 依赖项 | 风险描述 | 影响程度 | 应对措施 |
|---|---|---|---|
| 跨平台 PTY 稳定性 | Windows ConPTY 与 macOS/Linux PTY 在信号中断（`SIGINT`）和 ANSI 序列上存在行为差异 | 高 | 采用成熟跨平台 PTY 封装（`portable-pty` / `node-pty`），在 Stage 1 建立三端自动化终端回归测试 |
| 本机 `gopls` / Go 代理异常 | 国内网络访问 `proxy.golang.org` 易超时（原手册已实测暴露此问题） | 中 | 环境体检自动检测 `GOPROXY` 并一键提供配置建议；`gopls` 缺失时平滑降级为语法高亮 |
| 外部 Markdown 格式多样性 | 不同作者的 Markdown 结构差异导致章节或命令目录推断偏差 | 中 | 启发式推断 + 允许用户在 UI 临时点击修改 `cwd` 与运行模式，不强依赖专有语法 |

### 9.2 术语表
- **PTY（Pseudo-Terminal）**：伪终端，用于提供支持彩色输出、交互输入与进程信号控制的真实 Shell 环境。
- **LSP（Language Server Protocol）**：语言服务器协议，用于为编辑器提供代码补全、定义跳转、悬停文档与语法错误诊断（Go 语言对应 `gopls`）。
- **BYOK（Bring Your Own Key）**：用户自带模型 API Key，直接连接模型服务商或本地模型，不经由产品方中转。
- **四步学习法**：源自《Go 与 GoFrame 开发实践手册》的实践方法论——「先预测 → 再实现 → 用证据验收 → 解释原因」。
- **Daemon / Oneshot 命令**：前者指长期运行阻塞前台的服务进程（如 `go run .`），后者指执行完毕即返回退出码的短时命令（如 `curl`、`go test`）。
