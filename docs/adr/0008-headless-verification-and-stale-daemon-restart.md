# 无头隔离验收执行器与托管 Daemon 陈旧自动重启

在工程实战课程中，学习者常先启动 `go run .` 等常驻服务，修改代码保存后直接点击「运行验收」——此时旧进程仍在运行改前的代码，会导致令人困惑的假失败；同时若验收命令直接往用户交互终端灌入输出，会打断调试上下文。我们决定将自动化验收运行在独立的**无头进程组（Headless Runner）**中（不污染交互式 PTY），并由工作台追踪受管 **Managed Daemon** 的启动时间与工作区最近保存时间：当 `requiresDaemon` 验收发现托管服务未启动或代码已更新（Stale）时，自动重启受管服务并等待端口就绪后再执行断言；若目标端口被外部非工作台进程占用，则仅提示端口冲突，绝不强杀外部进程。

## Considered Options

- **无头验收 + 受管 Daemon 陈旧自动重启（已采纳）**：既消除「改了代码忘重启」的高频挫败感，又保持交互终端干净且不越权终止用户外部进程。
- **复用交互终端且纯手动重启**：实现略简单，但输出混杂且极易因旧二进制进程造成误判。

## Consequences

- `execution` 模块需维护 Managed Daemon 句柄表（PID/进程组、绑定端口、启动时间戳）并与 `workspace` 的保存时间戳对齐；非托管进程占端口必须走可恢复的冲突引导而非强制 `kill`。
- 无头验收进程必须运行在独立进程组 / Windows Job Object 中，保证超时熔断（`SIGINT → SIGKILL`）与退出清理 100% 可靠。
