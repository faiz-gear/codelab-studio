# 以信任边界与显式授权护栏替代 OS 级进程沙箱

PRD 使用了「沙箱」一词，但在 macOS / Windows / Linux 跨平台桌面环境中，强制通过容器或 OS 级策略隔离本地编译器、包管理器缓存与本地监听端口极易破坏正常研发工具链。我们决定明确不承诺 OS/容器级进程沙箱，将本地安全模型界定为三层护栏：① 外部/Git Course 在显式信任前锁定为只读预览态（信任记录按来源标识存于工作区外的全局 `trust.json`，防止课程包伪造）；② 工作台自身的文件 CRUD、监听、上下文采集与 ACP 代理严格校验工作区规范化路径并过滤敏感文件；③ 所有结构化命令入口（手册命令块、验收规则、ACP 命令执行）禁止静默高危执行并强制红色确认。

## Considered Options

- **信任边界 + 应用层路径边界 + 显式授权（已采纳）**：类 VS Code Workspace Trust 模型，安全承诺诚实透明且与原生开发工具链完全兼容。
- **OS / 容器级子进程沙箱**：为终端与判题子进程引入 `sandbox-exec`、Linux namespace 或 Docker 隔离。

## Consequences

- 一旦用户显式信任某外部课程包并执行其代码或命令，派生出的本地进程即以当前用户 OS 权限运行；高危命令拦截仅覆盖结构化入口，不对用户在交互式 PTY 中手动敲入的原始击键流做脆弱拦截。
- 工作区外部软链接与 `../` 路径穿越在应用层文件服务与 ACP 文件代理中被严格阻断。
